# 포트폴리오 시연 가이드

WaferScope는 반도체 검사 데이터를 탐색하고 재현 가능한 분석 설정을 보관하는 로컬 데이터 워크벤치입니다.
화면뿐 아니라 서비스 경계, 실제 DB, 실패 처리, 테스트 결과까지 함께 설명할 수 있도록 구성했습니다.

## 5분 시연

1. **Overview** — 실제 Oracle 데이터의 검사 수, 평균 수율, 분포와 서비스 상태를 보여줍니다. 최근 실행 P95는 저장된 이력에서 집계하며 측정 범위를 설명합니다.
2. **Datasets** — EDS 데이터에서 `LOT-101`을 조회하고 검색·정렬·페이지 이동·CSV를 보여줍니다. 기본 조회의 행 제한과 검색이 적용되는 범위를 설명합니다.
3. **Analysis** — category를 바꾸면 별도 DOM의 차트로, legend를 바꾸면 각 차트의 시리즈로 나뉘는 것을 보여줍니다. 변경 후 명시적으로 실행하며 이전 결과를 새 설정의 결과로 오인하지 않도록 상태를 구분합니다.
4. **Scale** — 1천/1만/10만/100만 행을 선택합니다. 필터·결측 제외를 제외한 전체 건수의 일치와 페이지 전송·대량 그리기를 설명합니다.
5. **Saved views / Activity** — 메모와 함께 저장하고 새로고침·직접 링크로 복원합니다. API console에서 DuckDB Left join을 실행한 뒤 이력에서 같은 요청을 다시 엽니다. PNG로 내보내며 한글도 확인합니다.

이미 준비된 예제 뷰는 `검사 수율 · LOT-101`, `백만 행 · 제품별 분포`, `결함 현황 · 심각도별`입니다.
예제는 합성 데이터임을 표시하며 가짜 고객이나 성과 지표는 사용하지 않습니다.

## 설계 질문에 답할 근거

| 질문 | 구현과 설명 포인트 |
| --- | --- |
| 왜 서비스를 나눴나? | DAC는 Oracle·DuckDB, Chart는 시각화 중립 모델, Portal은 사용자 상태와 요청 실행, renderer는 이미지 생성 책임을 가집니다. 각 경계에 HTTP 계약과 독립 배포 단위가 있습니다. |
| ECharts 교체는 가능한가? | chart-worker 응답은 category/series/points 모델입니다. 웹과 SSR 어댑터를 바꾸면 되지만 렌더링·상호작용 회귀 검증은 필요합니다. |
| 백만 행은 어떻게 처리했나? | 실제 Oracle 테이블을 페이지 단위로 끝까지 조회하고 모든 행을 범주·레전드별로 그룹핑합니다. |
| 왜 DuckDB로 모든 그룹핑을 하지 않았나? | 현재 페이지 단위 입력과 typed dictionary 그룹핑을 사용합니다. DuckDB 비교 실험은 아직 하지 않았으므로 더 빠르다고 주장하지 않습니다. |
| 저장 충돌은? | PostgreSQL UPDATE/DELETE의 WHERE 절에 expected version을 포함하고 불일치 시 409를 반환합니다. |
| 실패 시 사용자는 무엇을 보나? | 실행 상태·응답·소요 시간·요청을 이력에 남깁니다. 잘못된 입력, 서비스 오류, 빈 결과, 적용 전 설정을 별도로 보여줍니다. |
| 실제 검증은? | .NET 102개, 프런트엔드 5개, 실제 통합 23개, 브라우저 28개 검사와 재배포 영속성 검증 결과를 제공합니다. |
| 운영 전 필요한 것은? | 인증/권한·TLS·버전 관리 마이그레이션·백업 복구·부하 시험·관측 체계를 설계해야 합니다. 현재 구현과 다음 작업을 구분합니다. |

## 지원 직무별 설명의 초점

- 반도체 데이터/제조 SW: EDS·결함 데이터 관계, 웨이퍼/로트 분할, 전체 행의 누락 방지, 재현 가능한 분석.
- 플랫폼/백엔드: 서비스 계약, PostgreSQL 낙관적 동시성, 요청 제한, 오류 전파, Kubernetes 배포와 상태 확인.
- 데이터/시각화: 타입에 따른 축 처리, 독립 차트 수명 관리, 전체 점 처리와 렌더링 비용, 웹/이미지 어댑터 분리.
- 금융·거래 데이터 직무: 입력 검증, 정확한 건수와 처리 범위, 감사 가능한 실행 이력과 재현성. 이 시스템이 거래 엔진의 지연시간·정합성 요건을 충족한다고 주장하지 않습니다.

특정 기업의 실제 시스템을 연동했거나 채용 수준을 보장하는 프로젝트로 소개하지 않습니다.
직접 설명할 수 있는 선택·실험·실패·개선점을 중심으로 소개하고, 구현 도구나 AI 사용 여부를 질문받으면 실제 작업 방식을 정확히 설명합니다.
