## 규모별 로컬 관측

`python3 scripts/portal-scale-check.py`로 크기별 요청을 한 번씩 순차 실행했습니다.

브라우저 ECharts 렌더링 시간은 포함하지 않습니다. 워밍된 서비스의 단일 관측값이며 부하 테스트가 아닙니다.

## 알려진 범위

- 인증 없는 로컬 공유 워크스페이스이며 다중 테넌트 권한 체계는 없습니다.
- 실제 Oracle/PostgreSQL을 사용하지만 데이터는 합성 데이터입니다.
- 카테고리/레전드 그룹핑은 .NET에서 수행합니다. DuckDB는 기본 데이터의 조인·병합·필터에 사용합니다.
- 대량 시각화는 결정적 해시 샘플이므로 희귀 결함·극단값을 반드시 보존하지는 않습니다.
- PNG/SVG/HTML은 적용된 전체 설정으로 생성합니다. 웹에서 임시 변경한 줌/레전드 숨김 상태는 반영하지 않습니다.
- Vite 분석 모듈은 약 547KB(압축 약 185KB)로 크기 경고가 있습니다. 분석 화면을 열 때 지연 로딩합니다.
- 통합 테스트가 만든 의도적 실패도 실제 실행 이력과 오류 지표에 포함됩니다.
- HA, 공개 서비스 인증/TLS, 자동 백업·복구 훈련, 장시간 동시 부하 테스트는 별도 작업입니다.

## 포인트 크기·라벨과 브라우저 성능

2026-11-13: 포인트 자동 크기 또는 2–20px, 라벨 표시, 라벨 컬럼, 8–20px 글꼴을 추가했습니다.
설정은 저장된 뷰와 PNG/SVG/HTML에 반영됩니다. 표시 라벨은 최대 120자로 제한하고 겹치는 라벨은 숨깁니다.
기본값은 라벨 꺼짐이며, 라벨을 켜면 전체 라벨 배치를 위해 progressive drawing을 끕니다.

- .NET 테스트 122개 통과: DAC 39 / Chart 56 / Portal 27.
- 옵션 브라우저 검사 6개 통과: 크기·라벨·폰트 적용, SVG 라벨, PNG, 뷰 저장/복원, 모바일 너비, 런타임 오류.
- 증거: `artifacts/chart-options-browser.json`, `artifacts/chart-options-browser.png`, `artifacts/chart-options.svg`.

Chromium 158, 1600×1100, 독립 차트 1개에 모든 반환 점을 표시했습니다. 포인트 6px,
라벨 컬럼 waferId, 글꼴 11px, 범례 product. 각 조건을 3회 순차 실행한 중앙값입니다.
`renderMs`는 ECharts setOption 직전부터 첫 finished까지이며, 사용자 클릭부터 응답·렌더링 후
두 프레임까지의 시간은 자동화 비용도 포함합니다. 동시 부하나 프레임률 검사는 아닙니다.

| Oracle 원본 행 | 표시 점 | 라벨 OFF 그리기 | 라벨 ON 그리기 | 클릭→표시 OFF / ON |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 1,000 | 15.6ms | 41.1ms | 162 / 162ms |
| 10,000 | 10,000 | 107.2ms | 329.2ms | 435 / 908ms |
| 100,000 | 20,000 | 386.9ms | 711.4ms | 796 / 1,863ms |
| 1,000,000 | 20,000 | 364.6ms | 717.4ms | 948 / 2,048ms |

2만 점에 라벨을 켜면 그리기 비용이 약 2배이고 메인 스레드의 긴 작업은 약 0.72초였습니다.
따라서 라벨은 기본으로 끄며, 차트를 나누거나 필터링한 뒤 켜는 편이 반응성이 좋습니다.
20,000점 조건에서 라벨 문자열을 포함한 JSON 응답도 약 575KB → 955KB로 증가했습니다.
이 수치는 현재 로컬 하드웨어·표본·브라우저에 대한 관측이며 다른 컴퓨터의 결과는 달라질 수 있습니다.

재실행: `PLAYWRIGHT_MODULE=/tmp/dac-browser/node_modules/playwright node scripts/chart-render-performance.cjs`.
전체 원시 기록: `artifacts/chart-render-performance.json` (24회, 브라우저 오류 없음).
